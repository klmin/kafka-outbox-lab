# 개념 정리

케이스를 진행하면서 확인한 내용으로 계속 고친다. 각 항목 끝의 `→ 케이스 NN`은 직접 재현한 곳.

---

## 1. 전달 보장

| 방식 | 오프셋 커밋 시점 | 결과 |
|---|---|---|
| at-most-once | 처리 **전** | 처리 중 죽으면 **유실** |
| at-least-once | 처리 **후** | 처리 후 커밋 전에 죽으면 **중복** |
| exactly-once | Kafka 트랜잭션 | Kafka → Kafka 처리에서만. **DB 까지는 못 묶는다** |

- 실무 기본은 **at-least-once + 멱등 처리**. 처리 후 커밋해도 중복은 막지 못한다(DB 커밋과 오프셋 커밋 사이에 죽을 수 있다). → 케이스 01, 02
- 이 저장소 설정: `enable-auto-commit: false`, `ack-mode: record`(리스너가 정상 반환하면 커밋)

## 2. 이중 쓰기(dual write)와 Transactional Outbox

- DB 저장과 Kafka 발행은 한 트랜잭션으로 묶을 수 없다.
  - DB 커밋 후 발행 실패 → 이벤트 유실
  - 발행 후 DB 롤백 → 없는 데이터의 이벤트가 나감
- 아웃박스: 업무 데이터와 **같은 DB 트랜잭션**에 발행할 메시지를 `outbox` 테이블에 INSERT → 커밋 후 relay 가 Kafka 로 발행. → 케이스 03, 04
- relay 방식
  - 폴링: 스케줄러가 미발행 행을 읽어 발행. 여러 대면 `FOR UPDATE SKIP LOCKED` → 케이스 05
  - CDC(Debezium): DB 로그(WAL)를 읽어 발행. INSERT 직후 지워도 됨 → 케이스 11
- relay 도 발행 후 표시 전에 죽으면 **다시 보낸다**. 그래서 받는 쪽 멱등 처리가 여전히 필요.
- 아웃박스가 항상 필요한 건 아니다. DB 변경과 발행이 원자적이어야 할 때만. 로그, 클릭 이벤트처럼 DB 와 묶이지 않으면 바로 발행해도 된다.

## 3. 멱등 컨슈머

- 메시지마다 고유 ID(보내는 쪽 outbox.id)를 헤더에 싣는다.
- 받는 쪽은 `processed_message`에 ID 를 **업무 변경과 같은 트랜잭션**에서 INSERT. PK 충돌이면 이미 처리한 것이니 건너뛴다. → 케이스 06
- 트랜잭션이 따로면 소용없다(업무 커밋 후 ID 기록 전에 죽으면 다시 처리).
- 업무 키로 멱등을 보장하는 방법도 있다(예: `order_id` PK, 상태 전이 조건부 UPDATE).
- `processed_message`는 토픽 보존 기간보다 길게 두고 지운다.

## 4. 재시도와 DLT(Dead Letter Topic)

- 재시도할 오류(DB 일시 장애, 타임아웃)와 바로 DLT 로 보낼 오류(역직렬화 실패, 잘못된 데이터)를 나눈다. → 케이스 07
- 블로킹 재시도(같은 자리에서 백오프) vs 논블로킹 재시도(retry 토픽): 블로킹은 그동안 파티션 뒤 메시지가 밀린다.
- 처리할 수 없는 메시지(poison pill)가 파티션을 영원히 막지 않게 한다.
- DLT 는 쌓기만 하면 의미 없다. **알림 + 재처리 경로**가 있어야 한다.

## 5. 순서

- 순서는 **파티션 안에서만** 보장된다. 같은 주문의 이벤트는 같은 키(aggregate ID) → 같은 파티션. → 케이스 08
- 프로듀서 재전송 시 순서가 뒤집히지 않으려면 `enable.idempotence=true`(이 저장소 기본값).
- 컨슈머를 병렬화(파티션 수보다 많은 스레드)하면 순서가 깨질 수 있다.

## 6. 컨슈머 그룹과 리밸런싱

- 파티션 하나는 그룹 안 컨슈머 하나만 읽는다. 컨슈머 수 > 파티션 수면 남는 컨슈머는 논다.
- 컨슈머가 추가, 종료되거나 `max.poll.interval.ms` 안에 poll 하지 못하면 리밸런싱 → 커밋 안 된 메시지는 다른 컨슈머가 다시 처리(중복). → 케이스 09

## 7. 프로듀서 설정

- `acks=all`: 모든 ISR 에 기록돼야 성공.
- `enable.idempotence=true`: 프로듀서 재전송으로 같은 메시지가 브로커에 두 번 쓰이는 것 방지. **컨슈머 쪽 중복은 막지 못한다.**

## 8. 모니터링

- 컨슈머 lag(쌓인 메시지 수), DLT 적재 수, 아웃박스 미발행 행 수와 가장 오래된 행의 나이. → 케이스 10
