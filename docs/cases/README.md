# 케이스 목록

순서대로 진행한다. 케이스마다 `NN-이름.md` 파일을 만들고 아래 템플릿으로 기록한다.
테스트는 `src/test/java/com/klmin/kafkalab/caseNN/` 에 둔다.

| # | 케이스 | 확인할 것 | 상태 |
|---|---|---|---|
| 01 | at-least-once 중복 | 처리 후 오프셋 커밋 전에 죽으면 같은 메시지가 다시 온다 | ⬜ |
| 02 | 처리 전 커밋 시 유실 | 커밋을 먼저 하면 처리 실패 시 메시지가 사라진다 | ⬜ |
| 03 | 이중 쓰기 문제 재현 | DB 저장 + 직접 발행: 롤백인데 발행됨 / 커밋됐는데 발행 실패 | ⬜ |
| 04 | Transactional Outbox (폴링 relay) | 03 을 아웃박스로 해결. 롤백되면 발행 안 됨, 커밋되면 결국 발행됨 | ⬜ |
| 05 | relay 여러 대 | `FOR UPDATE SKIP LOCKED` 없을 때 중복 발행, 있을 때 분배 | ⬜ |
| 06 | 멱등 컨슈머 | 같은 메시지를 두 번 보내도 업무 반영은 한 번 (`processed_message`) | ⬜ |
| 07 | 재시도와 DLT | 일시 오류는 재시도 후 성공, 영구 오류·역직렬화 실패는 DLT | ⬜ |
| 08 | 순서 보장 | 같은 키는 순서 유지, 키 없이 보내면 섞임 | ⬜ |
| 09 | 리밸런싱 중복 | 처리 중 컨슈머 추가·종료 시 커밋 안 된 메시지 재처리 | ⬜ |
| 10 | lag 관찰 | 느린 컨슈머에서 lag 증가를 지표와 Kafka UI 로 확인 | ⬜ |
| 11 | (선택) Debezium CDC relay | 폴링 relay 와 지연, DB 부하 비교 | ⬜ |
| 12 | (선택) Kafka 트랜잭션의 한계 | read-process-write 는 exactly-once, DB 쓰기는 묶이지 않음 | ⬜ |

상태: ⬜ 안 함 · 🟨 진행 중 · ✅ 완료
